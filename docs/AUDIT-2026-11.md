# Аудит MasterBook — ноябрь 2026

Проверено по коду, базе (live Supabase) и реальными запросами к серверу записи на изолированном тестовом мастере. Чужие данные не менялись.

## Архитектура

```
Клиент (браузер) ──► web/ (Next.js 14, Vercel, ISR 60 с)
                       │  чтение: anon-ключ → profiles/services/reviews (RLS: только published)
                       │  запись: POST /functions/v1/book (edge, service-role, строгая валидация)
                       ▼
                 Supabase (Postgres + Auth + Storage + Edge Functions)
                       ▲  book_appointment(): advisory-lock + проверка пересечения + insert
                       │
Мастер ──► app/ (Expo SDK 54) — локальная БД на телефоне + инкрементальный синк
           (push по меткам, pull по server_updated_at при входе / возврате из фона / pull-to-refresh)
Мастер ──► web/cabinet — тот же Supabase-аккаунт, правит profiles/services напрямую
```

Ключевой момент: у профиля мастера **два источника правды** — телефон (useSettingsStore) и таблица profiles. Телефон пишет в profiles, но никогда не читает из неё.

## Проблемы

### P1 — ломают основные сценарии

1. **Сайт предлагает занятое время.** `web/components/BookingForm.tsx` строит слоты только из рабочих часов: занятые, перерыв и буфер видны как свободные. Клиент узнаёт «занято» только после отправки и перебирает время вслепую. → Серверная функция свободных слотов, форма показывает только реальные окна.
2. **График из приложения не доходит до сайта.** `app/settings/work-hours.tsx:73` сохраняет только на телефоне; на сервер часы уходят лишь при «Опубликовать» (`cloudSync.ts:597`). Мастер сменил часы → сайт принимает записи по старым. → Пушить расписание при сохранении.
3. **Мастер не узнаёт о записи с сайта.** Нет уведомления, бейджа, realtime; синк только при открытии/возврате (не чаще 5 мин). Запись с сайта неотличима от обычной. А сайт обещает «мастер подтвердит запись». → Локальное уведомление «Новая запись с сайта» после синка + честный текст на сайте; серверные push — следующим шагом (нужна сборка).
4. **Новый телефон / переустановка ломают публичный профиль.** Первый синк шлёт `name: ''` (`cloudSync.ts:301`) — в каталоге мастер без имени; затем «Опубликовать» генерирует новый slug — старая ссылка, разосланная клиентам, умирает. → Не затирать пустыми значениями; восстанавливать профиль с сервера при входе.
5. **Фальшивые отзывы.** RLS `Master manages own reviews` (ALL) + гранты INSERT/UPDATE: мастер может создать себе отзыв с любой оценкой и удалить плохой. Настоящего сбора отзывов от клиентов нет (0 отзывов). → Закрыть запись мастеру.
6. **Восстановление пароля не доходит до людей** (конфиг, не код): Site URL = localhost:3000, нет SMTP. → Хэнд-офф.
7. **Нельзя закрыть даты / поставить запись на паузу.** Отпуск, болезнь — клиенты продолжают записываться; единственный способ — снять страницу с публикации. → Флаг «пауза записи» + закрытые даты (сервер + кабинет).

### P2

8. Буфер между записями не учитывается сервером (сценарий 3).
9. Часовой пояс зашит UTC+5 (`book/index.ts:35`) — для Москвы (+3), Новосибирска (+7), Бишкека (+6) «сегодня/прошло» считается неверно.
10. Перенос записи в приложении не переносит напоминание и не проверяет перерыв/выходной (`appointment/[id].tsx:186,335`).
11. Правки из веб-кабинета затираются следующим «Опубликовать» в приложении (телефон пушит всё из локальной копии).
12. Клиент не может сам отменить/перенести запись; подтверждение — только экран (нет SMS/письма).
13. `book` загружает всех клиентов мастера ради поиска по телефону (есть индекс phone_digits, не используется); нет лимита на один номер.
14. Поиск: нет фильтров по цене и доступности; сортировка «по рейтингу» бессмысленна без отзывов.
15. Страница мастера: нет адреса (только город/район), нет условий отмены, нет og:image — ссылка в WhatsApp без превью.
16. Цена услуги обязана быть > 0 — бесплатную консультацию не завести.
17. «Опубликовать» сохраняет локально до ответа сервера — при ошибке телефон считает профиль опубликованным.
18. Колонки расписания в profiles есть в базе, но их нет в миграциях репо (дрейф схемы).
19. Неудачный пуш не повторяется до следующей правки/возврата из фона.

### P3

20. Аватар не синкается — на сайте инициалы.
21. Статус no-show есть в типах, но не выставляется нигде.
22. У услуги нет описания и фото.
23. Каталог показывает все города, а не город посетителя по умолчанию.

| UX/UI | 7 | Единая система Atelier, фото, ясные CTA; запись — нативные date/select |
| Клиентский сайт | 6 | Понятный, быстрый; не показывает реальную доступность |
| Приложение мастера | 6 | Богатый CRM; слабая связь с сайтом |
| Регистрация | 7 | Сайт + приложение; восстановление пароля упирается в конфиг |
| Поиск | 5 | Категория, город, текст; нет цены/доступности |
| Воронка записи | 5 | Сервер надёжен, интерфейс не знает о занятости |
| Управление услугами | 6 | CRUD, пресеты по специализации; нет описания/фото/вкл-выкл |
| Расписание | 4 | Один интервал на все дни; нет дат-исключений, паузы; не синкается |
| Синхронизация | 4 | Профиль однонаправленный, нет уведомлений |
| Backend | 7 | Атомарная запись, валидация на сервере |

## План исправлений (этот заход)

1. P1-1, P2-8, P2-9, P2-13: серверная функция свободных слотов; `book` учитывает буфер, часовой пояс по городу, ищет клиента по индексу, лимит на номер; форма записи — выбор дня и сетка свободного времени.
2. P1-5: закрыть мастеру запись в reviews.
3. P1-7: пауза записи и закрытые даты (сервер + веб-кабинет).
4. P1-2, P1-4, P1-3 (локально), P2-10: приложение — пуш расписания при сохранении, не затирать профиль пустым, восстанавливать профиль с сервера, уведомление о записи с сайта, перенос напоминания.
5. P1-3 (текст), P2-15: честный текст про подтверждение, og:image.

Следующие заходы: серверные push (нужна сборка), отзывы от клиентов после визита, отмена записи клиентом по ссылке, фильтры цены/доступности, разные часы по дням недели.
