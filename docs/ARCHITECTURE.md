# Архитектура MasterBook

Документ для того, кто видит проект впервые. Цель — за час понять, что где лежит,
как течут данные и обо что тут уже спотыкались.

## Что это за продукт

MasterBook — CRM для частного мастера (маникюр, барбер, репетитор, фотограф).
Мастер ведёт клиентов, записи, услуги и финансы у себя в телефоне. Отдельно есть
сайт-каталог: мастер может опубликовать профиль, и клиенты находят его и
записываются онлайн.

Приложение бесплатное. Деньги — за продвижение в каталоге: мастер пополняет
баланс переводом, владелец подтверждает вручную, мастер покупает премиум и
поднимается в выдаче. Подробности модели — [MASTERPLAN.md](MASTERPLAN.md).

## Три деплоя

Репозиторий держит три независимо выкатываемые вещи:

| Что | Где | Чем собирается |
|---|---|---|
| Мобильное приложение | `app/`, `src/` | EAS Build → App Store / Google Play |
| Сайт-каталог | `web/` | Next.js 14, отдельный `package.json` |
| База и серверная логика | `supabase/` | миграции + Deno edge-функции |

`web/` — **отдельное приложение** со своими зависимостями и своим алиасом `@/`
(он указывает на `web/`, а не на корень). Не путай `@/lib/...` (сайт) и
`@/src/lib/...` (приложение) — это разные деревья.

## Мобильное приложение

### `app/` — только маршруты

Файловая маршрутизация expo-router. Один файл = один экран. Здесь не должно быть
бизнес-логики сложнее, чем «собрать данные из сторов и отрисовать».

```
app/
  _layout.tsx            корневой layout: тема, i18n, гейты, инициализация
  (auth)/                онбординг: welcome → login/register → профессия → услуги
  (tabs)/                четыре вкладки: index (Сегодня), calendar, clients, finances, profile
  appointment/           новая запись (мастер из 4 шагов) и карточка записи
  client/                карточка, создание, импорт из контактов
  finance/               операция и налоговый отчёт
  settings/              валюта, язык, рабочие часы, напоминания, календарь, аккаунт
  publish.tsx            публикация профиля в каталог
  insights.tsx           аналитика бизнеса
```

### `src/` — всё остальное

```
src/
  stores/       Zustand + persist. Источник правды на устройстве.
  lib/          Бизнес-логика и работа с внешним миром (см. ниже).
  components/   Переиспользуемые компоненты; ui/ — дизайн-система.
  hooks/        Тонкие обёртки: useT, useAlert, useTabBarOffset и т.п.
  i18n/         Переводы. locales/{ru,en}.json + extra/ по экранным кластерам.
  theme/        Цвета, типографика, отступы, тени.
  types/        Доменные типы (Client, Appointment, Service, FinanceEntry).
  data/         Статические данные: профессии, шаблоны услуг, страны и города.
  utils/        Чистые функции без побочных эффектов: даты, деньги, время, сортировка.
```

`src/lib/` сгруппирована по назначению, а не свалена в одну папку:

| Папка | За что отвечает |
|---|---|
| `sync/` | облачная синхронизация, слияние last-write-wins, хранилище для persist |
| `reminders/` | локальные уведомления и напоминания клиентам |
| `media/` | фото: локальное хранение, приватный бакет, публичное портфолио |
| `integrations/` | системный календарь, контакты, карты |
| `account/` | вход, биометрия, троттлинг попыток, удаление аккаунта |
| `reports/` | аналитика, «спящие» клиенты, налоговый PDF, экспорт данных |
| `dev/` | сидеры демо-данных (в проде не вызываются) |
| корень `lib/` | `supabase.ts` (клиент), `validation.ts` (Zod-схемы), `crashReporter.ts`, `haptics.ts`, `professionPacks.ts` |

### Как течут данные

```
экран → стор (Zustand) → AsyncStorage        ← источник правды на устройстве
                ↓ (отложенный пуш)
         src/lib/sync/cloudSync.ts
                ↓
            Supabase
                ↓ (публичные строки)
          сайт-каталог web/
```

Приложение **local-first**: оно полностью работает без сети и без аккаунта.
Облако — это резервная копия и мост к сайту, а не источник правды.

Синхронизация (`src/lib/sync/cloudSync.ts`):

- `syncNow()` = сначала pull, потом push. Дёргается при входе, при возврате из
  фона (не чаще раза в 5 минут) и по pull-to-refresh.
- Конфликты — last-write-wins по `updated_at` (`sync/syncMerge.ts`).
- Удаления едут как tombstones (`deleted_at`), иначе удаление «воскресало» бы
  со второго устройства.
- Публичный профиль пушится **отдельным** запросом (`pushPublicProfile`), а не
  общим синком: иначе второе устройство со старым локальным `published`
  молча снимало бы мастера с публикации.

**Обмен инкрементальный, но с подстраховкой.** Это самое хрупкое место в проекте:
ошибка тут не падает, а молча не отправляет или не забирает строку.

- Отправка. Частый отложенный пуш шлёт только строки с `updatedAt` новее метки
  прошлой успешной отправки. Метки — по таблице и по аккаунту. Сравниваются два
  значения ОДНИХ часов (и время правки, и метку ставит само устройство), поэтому
  расхождение часов между устройствами роли не играет. Опасен только перевод
  часов назад на самом устройстве — на этот случай `syncNow` и `flushPush`
  делают ПОЛНЫЙ пуш.
- Выгрузка. Фильтр по `server_updated_at` — её ставит триггер в БД. Клиентский
  `updated_at` для этого не годится: устройство с убежавшими вперёд часами
  записало бы строку с будущим временем, второе подняло бы по ней свою метку и
  навсегда перестало видеть нормальные строки. Три страховки: метка отматывается
  на минуту назад (гонка коммитов), метка старше 30 дней считается протухшей
  (иначе пропустим удаления, которые чистятся через 90 дней), и раз в сутки
  выгрузка полная в любом случае.
- Метки живут в `useSyncStore` (`pushMarks`, `pullMarks`, `lastFullPullAt`),
  переживают перезапуск и стираются при выходе — иначе следующий аккаунт на том
  же устройстве начал бы с чужой меткой.

## База данных

Схема — только в `supabase/migrations/`. Правила и ловушки:
[supabase/README.md](../supabase/README.md). Прочитай его до первого изменения БД.

Коротко о безопасности: RLS ограничивает **строки** (мастер видит своё),
колоночные гранты ограничивают **колонки** (мастер не может выписать себе
премиум или рейтинг). Деньги двигают только SECURITY DEFINER-функции;
`confirm_payment` вызывается исключительно из edge-функции под service-role.

## Что уже стреляло

Это не теория — каждый пункт стоил инцидента.

**Тесты не видят сломанную синхронизацию.** В тестах `supabase` замокан, поэтому
любая проблема прав в БД проходит мимо CI. Синк однажды не работал ни у кого
десять часов при полностью зелёных тестах. Единственный способ поймать — запустить
приложение и посмотреть лог Metro на `permission denied`.

**Ответ 2xx не значит «получилось».** PostgREST отвечает 204 и когда правило
доступа отфильтровало все строки. Проверять результат записи надо запросом к базе.

**`upsert` пишет во все колонки тела**, включая `id`, `user_id`, `created_at` —
меняешь колоночные гранты, сверься с тем, что реально шлют `*ToRow` в `cloudSync`.

**Валидация может существовать и не работать.** `serviceSchema` была написана,
покрыта тестами и не вызывалась ни из одного экрана — в базе появлялись услуги
длительностью 200000 минут. Написал схему — проверь, что её кто-то зовёт.

**Инлайновые стрелки в списках.** `ItemSeparatorComponent={() => ...}` создаёт
новый тип компонента на каждый рендер, и React перемонтирует все разделители.
Выноси в константу модуля или в `useCallback`.

## Запуск и сборка

```bash
npm install
cp .env.local.example .env.local     # подставить ключи Supabase
npx expo start                       # Metro
```

| Команда | Что делает |
|---|---|
| `npm test` | Jest |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run doctor` | `expo-doctor` — совместимость версий с Expo SDK |
| `npm run build:ios` / `build:android` | EAS-сборка production |
| `npm run submit:ios` / `submit:android` | отправка в сторы |

CI (`.github/workflows/ci.yml`): типы, тесты, expo-doctor, сборка сайта и
сверка версий. Держи зелёным — расхождение версий Expo SDK ломает его чаще всего.

## Соглашения

- **TypeScript строгий.** Без `any`, `@ts-ignore`, `as unknown`. Если тип не
  сходится — это сигнал, а не помеха.
- **Комментарии объясняют «почему», а не «что».** Что делает код — видно из кода.
- **Тексты интерфейса — только через `useT()`**, никакого захардкоженного русского.
  Русские формы множественного числа настроены (`src/i18n/index.ts`), для
  количеств используй объект `{one, few, many}`, а не свою функцию.
- **Каждому `.start()`/`setInterval`/подписке — парная очистка** в `useEffect`.
- **Пул-реквест не готов, пока не запущено приложение.** Зелёные тесты не заменяют.

## Открытые вопросы и долги

- **Политика конфиденциальности живёт в другом репозитории**
  (`jumakho2013-alt/masterbook-privacy`), и опубликованная версия старее обеих
  копий здесь. Нужно решить, что канонично, и свести к одному месту.
- **Sentry подключён, но выключен**: нет `EXPO_PUBLIC_SENTRY_DSN`. Пока его нет,
  модуль телеметрии не выполняется и о падениях у пользователей никто не узнаёт.
  Чтобы включить:
  1. завести проект в Sentry, взять DSN;
  2. `eas env:create --scope project --name EXPO_PUBLIC_SENTRY_DSN --value "..."`;
  3. в `app.json` у плагина `@sentry/react-native` дописать `organization` и
     `project` — без них сборка ругается и не заливает source-map, а значит
     стек-трейсы в отчётах будут минифицированными и почти бесполезными.

  Код включится сам, менять его не надо. Пока DSN нет, пакет всё равно попадает
  в бандл (+1.4 МБ): Metro собирает require статически. Если решишь, что телеметрия
  не нужна — удаляй пакет и плагин целиком, а не оставляй лежать.
- **Офлайн-очереди операций нет**: правки без сети ждут следующего успешного пуша.
- **Тестов мало** относительно объёма: покрыты чистые функции и слияние, экраны — нет.
